# Seal Playerok Bot — Render patch

Этот ZIP — **патч**, а не полный исходный проект. Он содержит только новые/заменяемые файлы.
Сначала скачай/клонируй свой репозиторий `ddicq/Seal-Playerok-Bot`, затем скопируй содержимое
архива в корень проекта с заменой `paths.py` и добавлением остальных файлов.

## Что меняется

- `paths.py`: все изменяемые данные (настройки, статистика, логи, кэш) хранятся в `/var/data`.
- `render_start.py`: создаёт конфигурацию из переменных окружения и запускает исходный `bot.py`.
  Интерактивная настройка в терминале Render не используется.
- `render.yaml`: описывает Render Background Worker с Persistent Disk.
- `.python-version`: фиксирует Python 3.12.10.

Файлы `bot.py`, `settings.py`, `requirements.txt` и функциональные модули не заменяются.
Код активации не обходится: нужен действительный код, выданный официальным ботом проекта.

## Переменные Render

Обязательные:
- `SEAL_ACTIVATION_CODE` — действительный код активации из `@SealPlayerokBot`.
- `TELEGRAM_BOT_TOKEN` — токен Telegram-бота.
- `TELEGRAM_BOT_PASSWORD` — пароль доступа к Telegram-боту (не короче 6 символов).

Дополнительные:
- `PLAYEROK_API_TOKEN`
- `PLAYEROK_COOKIES`
- `PLAYEROK_USER_AGENT`
- `PLAYEROK_PROXY`
- `TELEGRAM_API_MODE` — `direct`, `worker` или `proxy`; по умолчанию `direct`.
- `TELEGRAM_PROXY`
- `TELEGRAM_CUSTOM_API_URL` — URL собственного Cloudflare Worker, если используешь его.

Не вставляй токены в исходный код, GitHub или этот ZIP. Добавляй их в Render → Service → Environment.

## Развёртывание

1. В репозитории `ddicq/Seal-Playerok-Bot` добавь файлы из ZIP в корневую папку.
2. Проверь, что `paths.py` заменён, а остальные три файла добавлены.
3. На Render выбери **New → Blueprint** и подключи свой GitHub-репозиторий.
4. Render обнаружит `render.yaml`. Проверь план: создаётся Background Worker `seal-playerok-bot`
   и диск `/var/data` размером 1 GB.
5. Подтверди создание сервиса. Заполни обязательные переменные окружения.
6. После первого запуска смотри Logs. Не публикуй содержимое логов, если там есть токены/cookies.

## Важные ограничения

- Blueprint задаёт `plan: starter`, так как Persistent Disk не доступен на бесплатном Worker.
  Это платный тип ресурса Render; проверь стоимость в интерфейсе перед подтверждением.
- `PLAYEROK_API_TOKEN` и остальные Playerok-поля можно оставить пустыми на первом запуске,
  если будешь настраивать их через существующий интерфейс бота.
- ZIP не содержит токенов или пользовательских данных.
- Это адаптация инфраструктуры. Сам запуск на аккаунте Render не был выполнен и не может
  считаться проверенным до просмотра логов первого запуска.
